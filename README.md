# 止める設定（2026年10月4日の版）

Claude のデスクトップアプリの Code タブでは、動作モード（AI がどこまで確認なしで動くかの切り替え）によっては、ファイルを消すコマンドが確認画面なしで実行されることがあります。この設定を入れると、rm・Remove-Item で始まる削除のコマンドと、GitHub などへ送る git push で始まるコマンドは、どの動作モードでも、確認画面を出さずに拒否されます。会話で「やっていい」と伝えても、実行されません。

- 対象：Windows のパソコンで Code タブ（Claude Code。有料プランが要ります）を使い、AI に作業を任せている方です。プログラムを書かない方も対象です。
- 効く範囲：Code タブの会話です。Cowork タブの会話には、おそらく効きません（試していません）。
- 9月8日に私が公開した前の版（19行の設定）を入れている方は、先に「前の版を入れている場合」の節を読んでください。

**試した結果の要点**：2026年10月3日に、私のパソコン（Windows 11 Home）のテスト用のフォルダで試しました。「編集を受け入れる（Accept edits）」は、ファイルの書き換えなどを確認なしで進める動作モードです。このモードで削除を頼むと、入れる前は確認画面が出ないまま実行され、入れた後は拒否されました（何も消えていません）。「手動（Manual）」では、削除も送信も、入れる前は確認画面が出て、入れた後は出ずに拒否されました。書き方を変えた削除（例：前に `bash -c` が付いた形）は、入れた後も拒否されませんでした。

理由は [WHY.md](WHY.md)、効く範囲の表は [MAP.md](MAP.md) にあります。

```json
{
  "permissions": {
    "deny": [
      "Bash(rm *)",
      "PowerShell(Remove-Item *)",
      "Bash(git push *)",
      "PowerShell(git push *)"
    ],
    "disableBypassPermissionsMode": "disable"
  }
}
```

書き写す時は、1文字も変えないでください。ただし git push の2行だけは、まるごと入れなくてもかまいません（手で消す時は、その上の行の最後の「,」も消します）。deny（拒否の一覧）に書いた言葉で始まるコマンドが、拒否されます。Bash と PowerShell は、AI がコマンドを実行する道具の名前です。パソコンによって使う道具が違うため、両方の書き方で書いてあります。どちらを使うか分からなくても、入れる中身は同じです。

最後の `disableBypassPermissionsMode` の行は、確認を全部飛ばす動作モード「権限をバイパス（Bypass permissions）」に関わる行で、コマンドは拒否しません。公式の説明では、この行を入れると「権限をバイパス」を選べなくなります。私の画面では、入れた後もモードの一覧に「権限をバイパス」と、右に「有効にする」が出ていました（私のアプリでは、このモードをもともとオンにしていません。オンにした時に選べなくなるかは試していません）。一覧に出ていても、入れ直さなくてかまいません。

**防げないこと**
- 書き方を変えた削除・送信のコマンド（例：`bash -c 'rm -rf build/'`）。拒否された直後に、AI がこうした書き方で実行しようとすることがあります。意味の分からないコマンドは、許可しないでください。「拒否」を押し、AI に「止められた理由を書いて、残りは私に任せて」と頼んでください。
- 上書き・移動・名前の変更や、データベースやクラウドに置いたデータの削除。
- 自分でターミナル（コマンドを入力する画面）に入力したコマンド。
- パスワードや API キーなどの秘密の情報が、GitHub などへ送る中身に紛れ込むこと。

大事なフォルダは、別の場所にコピーしておいてください。公開されている不具合の報告に、AI が消したファイルがごみ箱を通らずに消えた、というものが1件あります。

## 入れ方

入れる場所は、ユーザーフォルダの中の .claude フォルダにある settings.json です。AI に送る文では、ユーザーフォルダを `%USERPROFILE%` と書いています。

ふだん AI に「GitHub に上げて」「push して」と頼んでいる方や、送るところまで AI に任せたい方は、git push の2行を入れないほうがよいです。入れると、その頼みが毎回拒否されます。迷ったら入れておいてください。あとで外せます。

1. 新しい会話を始め、動作モードを「手動」にします。入力欄の左下にある、いまの動作モードの名前を押し、一覧から「手動」を選びます（私の画面では、はじめは「自動（Auto）」でした）。手動にするのは、ほかの動作モードでは入れる前でも確認画面が出ないことがあり、違いが見えないためです。
2. 入れる前に、確認画面が出るかを見ておきます。次の文を送ってください。確認画面が出たら、「拒否」を押してください。存在しないファイルなので、何も消えません。

   ```
   存在しないファイル zz_none.txt を消すコマンドを1回だけ実行して（Bash なら rm ./zz_none.txt、PowerShell なら Remove-Item .\zz_none.txt -WhatIf）。
   ```

   GitHub などへ送ることがある方は、「`git push http://127.0.0.1:9/none.git` を1回だけ実行して」とも頼みます。使われていない宛先なので、どこにも届きません。

3. AI に次の文を送ります。settings_mae.json は、入れる前の設定の控えです（mae は「前」の意味です）。git push の2行を入れない場合は、文の終わりに「git push の2行は足さないで」と書き足します。

   ```
   %USERPROFILE%\.claude\settings.json に、次の順で設定を足して。
   1. 今の settings.json を同じ場所に settings_mae.json としてコピーする。
   2. permissions の deny に "Bash(rm *)"、"PowerShell(Remove-Item *)"、"Bash(git push *)"、"PowerShell(git push *)" を、permissions の中に "disableBypassPermissionsMode": "disable" を足す。前からある行は消さず、同じ行を2つにしない。
   3. 9月8日に公開された前の版の設定（19行）が入っていたら、一覧を見せて消すかを聞く。
   4. 書く前に変更点を、書いた後に全文を見せ、JSON として正しいかを確かめる。
   ```

4. AI は書く前に、変更点を見せます（私の試しでは、文章で見せました）。そこで、次の2つを確かめます。足される行に、上の設定の行がすべてあるか。前からあった行が消えていないか。消える行があれば、「前からあった行を消さずに足し直して」と頼みます。書き込みの確認画面では、その1回だけ許可するボタンを押してください（コマンドの確認画面では「一度だけ許可」という字でした）。「常に許可」は選ばないでください。

自分で書く場合は、メモ帳で同じファイルを開き、deny の一覧に4つの行を、permissions の中に最後の行を足します。`//` で始まる注釈や、最後の項目の後ろの `,` は、エラーになります。

## 確かめ方

入れた後に新しい会話を始め、動作モードを手動にして、「入れ方」の2と同じことを頼みます。確認画面が出ずに、AI が「拒否された」と返事をすれば、効いています。

入れた後も確認画面が出たら、AI に次の文を送ります。読んでよいかの確認画面が出たら、許可してください。

```
%USERPROFILE%\.claude\settings.json を読み、deny の行を一覧にして。書き換えないで。
```

一覧に上の設定の行があるかを見ます。あるのに確認画面が出た時は、そのコマンドを見てください。`Remove-Item` で始まっていれば、AI は PowerShell で実行しようとしています。あなたのパソコンでは、PowerShell の行が効いていないかもしれません。その時、PowerShell での削除と送信は拒否されません（Git Bash〔Bash を使うためのソフト〕が無いパソコンでは、AI は主に PowerShell を使います）。意味の分からないコマンドには「拒否」を押してください。設定は残しても守りは弱くなりません。外す時は settings_mae.json に戻します。

## 拒否された時

入れると、消すのも送るのも、自分で行うことになります。

- 消したい時：AI に「消さずに、作業中のフォルダの中の『けす候補』へ移して一覧を見せて。同じ名前の物は上書きせずに知らせて」と頼みます。中を見てから、自分で消します。
- 送りたい時：AI に「送る変更の一覧と、パスワードや API キー、個人情報が入っていないかを日本語で見せて」と頼みます。見てから自分で送ります。ターミナルをアプリのメニュー（公式の英語の説明では Views）から開き、`git push` と入力します。
- 「自動」では、送る中身によっては、アプリの自動判定（危なそうな操作をアプリが自分で判断して止める仕組み）が止めることがあります。自分で入力して送る時にも同じ判定がかかるとは、公式の説明に書かれていません。

## 外し方・直し方

- 全部外す：AI に「settings.json を settings_mae.json の中身に戻して」と頼みます。メモ帳では、settings_mae.json の中身をコピーし、settings.json の中身と置き換えて保存します。もともと settings.json が無かった場合は、足した行をすべて消します。
- 一部だけ外す：外したい行だけを消します。メモ帳で消す時は、上に書いた `,` の決まりに気をつけてください。外した後は、上の確かめ方をもう一度行い、確認画面が出る状態に戻ったかを見ます。
- 書き間違えた時：次の会話の始めに、設定の誤りを知らせる画面（英語では Settings Error）が出ます。誤りのある設定のまま使い続けると、この設定の行はどれも効きません。上と同じように、settings_mae.json の中身に戻してください。

## 前の版を入れている場合

9月8日に私が公開した前の版の設定（19行）を入れている場合は、先に settings.json のコピーを取ってください。前の版の行を消してから、この設定を足します。残すと、ふだんの `python3 …` のコマンドまで拒否したままになります。前の版のうち7行は、データを外へ送るコマンドの行です（`curl` の6行と `git remote add`）。消すと、これらは元の扱いに戻ります。確認画面が出るか、「自動」では自動判定に任されます。それでも、消すことをおすすめします。前の版の1行ずつの扱いは WHY.md にあります。

## 試したこと

試したこと以外の説明は、主に Claude Code の公式の説明（英語。2026年10月1日に AI に読ませたもの）によります。

試し方：テスト用のフォルダの `.claude\settings.json` にだけ、AI に設定を書き込ませました。ふだんの設定を変えないためです。試した会話には、私のふだんの設定も読み込まれていました。あなたのパソコンでは、結果が違うことがあります。

試した範囲：頼んだコマンドは、どれも AI が Bash で実行しようとしました。試せたのは `Bash(rm *)` と `Bash(git push *)` の2行です。送信は、動作モードが「手動」の時だけ試しました。

### 試せていないこと

- 「自動」での結果（公式の説明では、自動でも拒否されます）
- PowerShell の2行。公式の説明では、Git Bash が入っていない Windows では、AI は主に PowerShell でコマンドを実行します。そういうパソコンで働くのは、主にこの2行です。
  - 削除を拒否する `PowerShell(Remove-Item *)` の行：公式の例と同じ文字ですが、私のパソコンでは試せていません
  - 送信を拒否する `PowerShell(git push *)` の行：公式の書き方に合わせた文字ですが、私のパソコンでは試せていません
- PowerShell の `rm`・`del`（どちらも Remove-Item の短い別名）が拒否されるか。公式の説明では、PowerShell の行は、よく使う短い別名にもあてはまります。
- 「権限をバイパス」をオンにした時に、入れた後で選べなくなるか
- 自分でターミナルに入力した `git push`
- 設定ファイルを書き間違えた時に出る画面
- `bash -c` 以外の、書き方を少し変えた削除と、強制プッシュ（送り先の記録を上書きする送信）
- 勧めている場所（ユーザーフォルダの設定ファイル）に入れた時
- ターミナルを開くメニューの日本語の表示
